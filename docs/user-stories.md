# 用户故事：大家会怎么用它

每个故事都是一段真实的工作场景（共 11 个）：谁、遇到什么问题、对 Claude 说什么、skill 做了什么、怎样算成功。最后一节写**不适合用它的场景**。

---

## 1. 运营值守：门店电视上的实时大屏

**角色**：连锁品牌运营经理小林，管 24 家门店。
**痛点**：订单、会员都录在多维表格里。早高峰想看「哪家店在爆单、哪家店还没开张」，只能反复刷新表格、自己算。

> 「把我们的订单多维表格做成实时大屏，放在运营中心电视上，要深色、远看清楚：<多维表格链接>」

**skill 怎么做**
1. 读表结构：订单、门店、会员、明细，以及它们之间的关联关系
2. 建妙搭应用，把多维表格流式同步进应用数据库
3. 套零售连锁模板：经营总览 + 实时大屏，选「深海」风格（会议室投屏、无发光装饰）
4. 截图自检，确认 1920×1080 一屏放下

**成功标准**：门店在多维表格里录入一单，约 10 秒后大屏上营收跳动、订单流闪入这一单；断网超过 30 秒时，页头的状态点变黄。

## 2. 销售主管：周一例会不再手工做 PPT

**角色**：B2B 软件公司销售主管王总，带 5 个销售团队。
**痛点**：每周一要截多维表格、贴 PPT，算赢单率和回款率。口径每次都要解释一遍。

> 「用客户管理模板给我做个销售看板，周一例会投屏用，要简洁专业：<CRM 多维表格链接>」

**skill 怎么做**
1. 套客户管理模板，把模板里的表名、字段名对应到用户的 CRM 表
2. 写口径：赢单率 = 赢单 ÷（赢单 + 输单）；在途商机不随时间范围变化；回款率按全部合同累计
3. 选「晴空」风格 + 「管理层简报」排版，跑设计检查
4. 每个面板的副标题写清口径

**成功标准**：例会上直接打开链接，切「近 30 天 / 近 90 天」，季末冲刺高峰一眼可见；没人再问「这个数怎么算的」。

## 3. 项目经理：每天早上 5 分钟看清谁在拖延

**角色**：研发项目经理阿杰，同时盯 18 个项目、60 个人。
**痛点**：任务表有 1,800 行，逾期的、待验收积压的，要筛好几个视图才看得出来。

> 「做一个工作管理看板，我每天早上自己看，重点是逾期和成员负载」

**skill 怎么做**
1. 套工作管理模板，生成两个看板：「项目总览」和「成员工作台」
2. 逾期 = 计划截止早于今天且未完成，标成「越少越好」；在手任务标成「当前状态」，不做环比
3. 推荐「个人工作台」排版：待办指标在上，主列表占大半屏

**成功标准**：打开就能看到逾期 190 条、按负责人排好；点开「成员工作台」，就知道谁手上压了 25 条。

## 4. 数据同学：把旧的多维表格仪表盘「升级」，而且数字不能变

**角色**：数据分析师小周。多维表格里已经有一个「经营仪表盘」，老板天天看。
**痛点**：想要投屏、想换风格、想加实时，但最怕「换了系统数字对不上」。

> 「把多维表格里的『经营仪表盘』搬到妙搭上，数字要和原来一模一样」

**skill 怎么做**
1. `import_base_dashboard.py` 读出 9 个组件，生成需求说明、迁移报告和原值快照
2. 编译成妙搭看板，默认用「原始布局」，保持老板熟悉的位置
3. `verify_spec_board.py` 逐个面板核对，迁移报告里写明哪些图做了改进（例如原图按时间点分组太密，改为按天）

**成功标准**：核对结果 8/8 一致，报告可以直接转给老板；老板打开新看板，位置没变，只是多了实时刷新和风格切换。

## 5. 产品经理：开完需求会，看板就出来了

**角色**：业务中台产品经理 Coco，刚开完一场 40 分钟的「客户经营看板」需求会。
**痛点**：会上大家七嘴八舌，会后要整理需求文档、找开发排期，两周后才有第一版。

> 「根据昨天下午的看板需求会，出一个客户经营看板」

**skill 怎么做**
1. 用 lark-meeting 找到会议，读**逐字稿原话**，不只看 AI 总结
2. 按清单提炼：谁看、做什么决策、指标口径、预警规则（「三天没跟进就算超期」）、风格偏好（「老板爱看大气的」→ 人文调性 → 松针风格）
3. 口径没说清的，用选择框逐条问；画出 ASCII 线框图请她确认
4. 生成看板，附「需求溯源表」：每个图表对应会上谁说的哪句话

**成功标准**：当天下午就能把链接发回需求群，每个图都能追溯到原话。

## 6. 业务负责人：在飞书画板上画个样子，就有看板

**角色**：销售运营负责人 Mia，不会写需求文档，但习惯在飞书画板上画框框。
**痛点**：画完给开发看，开发问「这个框是柱状图还是条形图？『在途』包括哪些阶段？」来回好几轮。

> 「照着这块画板做个看板，数据在客户管理多维表格里：<文档链接>」

**skill 怎么做**
1. `whiteboard_to_wireframe.py` 读画板原生节点：9 个框分别识别成指标卡、折线趋势、排行、环形占比、漏斗、明细表。依据是标题关键词加图形特征（折线、左对齐的横条、圆环、梯形、网格）
2. `wireframe_to_spec.py` 把标题对到表和字段：「签约额」对到合同金额求和、按签约日期；「销售签约排行 Top10」对到按销售汇总合同金额、取前 10
3. 拿不准的变成 4 道选择题：赢单率、回款率怎么算，「在途」排除哪些阶段，明细表各列口径
4. 生成后出一张「画板草图 vs 生成的看板」对照图

**成功标准**：答完 4 道题就出看板，位置和她画的一样；数字和团队用的客户管理模板一致。

## 7. 从别家 BI 迁过来：拿一张截图就行

**角色**：IT 同学阿凯，公司要把部分报表从老 BI 迁到飞书。老系统导不出配置，只能截图。

> 「这是老系统里的项目周会看板截图，用工作管理多维表格的数据做一个一样的」

**skill 怎么做**
1. 读图识别 7 个面板：3 个指标卡（「86%」判断为比率）、双折线、部门柱状、Top8 排行、逾期清单
2. 两条线分别按创建日期和完成日期统计，一个面板放不下，于是询问是否拆开，确认后拆成两个趋势面板
3. 「逾期任务清单」识别为逐条记录清单：列出任务标题、负责人、计划截止，按截止日期排序。表里没有「逾期天数」字段，提示他可以在多维表格里加一个公式字段
4. 「按期完成率」用字段对字段比较（实际完成日期 ≤ 计划截止）算出来

**成功标准**：截图里的每个图都有对应面板；口径问题一次问完，没有返工。

## 8. 老板 / 高管：一个链接，手机上也能看

**角色**：公司 CEO，出差多，主要用手机看数。

> 「给老板做个驾驶舱，就放最关键的 6 个数，手机上能看」

**skill 怎么做**：从已有看板里挑 6 个指标卡和 2 张主图，排版选「单列聚焦」，风格选「松针」；用 `+access-scope-set` 只放开给老板本人。

**成功标准**：手机竖屏不用横向滚动，6 个数一屏看完，每个都带环比。

## 9. 推广者：一场 3 分钟的演示

**角色**：公司内部负责推广 AI 工具的同学（也就是这个项目的作者）。

> 「做个演示看板，数据要像真的，我要在部门会上演示」

**skill 怎么做**：一键造演示数据（零售连锁 2.1 万行 / 工作管理 / 客户管理，带早高峰、季末冲刺、新店试营业等业务规律），按 README 的「3 分钟演示脚本」准备好；开着 `simulate_orders.py` 持续下单。

**成功标准**：现场新增一单，5 秒后看板上就有；风格、排版当场切换；迁移核对「8/8 一致」当场给大家看。

## 10. 开发者：在模板上做二次开发

**角色**：前端工程师，要把看板接入公司自己的审批系统。

> 「在这个看板里加一个『待审批合同』面板，点进去跳到审批页」

**skill 怎么做**：在精排路线上改 `server/modules/dashboard` 的查询，复用 `TablePanel`，加一个按钮跳转；按妙搭规范跑类型检查、规范检查和截图自检后发布。

**成功标准**：改动只涉及业务代码，风格、排版、实时刷新这些能力自动继承。

## 11. 市场分析：数据在别人的网站上

**角色**：区域拓展负责人阿杰，要给管理层讲「下一家店开在哪个省」。
**痛点**：各省 GDP、人口、消费数据都在公开网页上，每次都是手工复制进表格，格式乱、单位不统一，更新一次要半天。

> 「把这个网页上的各省 GDP 表抓进多维表格，以后每季度更新一次，再做个看板：<网址>」

**skill 怎么做**（`web-to-base` → `miaoda-base-live-dashboard`）
1. 先做合规检查：robots.txt 是否允许、是否需要登录、有没有个人信息；不满足就停下，建议改用统计局的数据下载页
2. 列出页面里能抓的数据块（表格、结构化数据、列表）和前 3 行预览，用选择框让阿杰挑；去掉「合计」行
3. 推断字段类型：去千分位和单位变成数字，百分比单独标出；和阿杰确认用「地区」做主键
4. 新建多维表格写入，补「来源链接」「抓取时间」；再跑一次只更新、不重复
5. 把命令写成脚本按季度定时运行；数据进表后接着走看板流程

**成功标准**：第一次跑完 33 个地区全部入表，数字列能直接求和排序；重跑结果是「新增 0、更新 33」；页面改版导致列名对不上时，脚本报错停下而不是写进错数据。

## 不适合用它的场景

| 场景 | 更合适的做法 |
|---|---|
| 只想在多维表格里加几张图，不需要独立应用 | 多维表格原生仪表盘（`lark-base` 的 Dashboard） |
| 一次性的静态报告、一句话出一个页面 | 多维表格「AI 页面」 |
| 秒级以下的交易监控、告警推送 | 专门的监控系统（如 Grafana）；本项目刷新间隔是 5 秒、同步链路是秒级 |
| 数据不在多维表格（在数仓、业务库） | 直接用 BI 工具连数据源；或先把关键汇总写回多维表格 |
| 要抓需要登录、付费墙后面、或含个人信息的网页 | 用对方的官方 API / 导出功能，或取得书面授权；`web-to-base` 会拒绝这类抓取 |
| 千万行级明细的多维分析 | 数仓 + BI；本项目适合万到十万行级的经营数据 |
