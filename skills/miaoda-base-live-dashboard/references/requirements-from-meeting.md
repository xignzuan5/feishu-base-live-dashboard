# 从飞书会议梳理看板需求

目标：把一场（或几场）需求讨论会，变成一份可以直接生成看板的 `dashboard-spec.json`，**每个面板都能追溯到会上谁说了什么**。命令细节以 `lark-meeting` skill 为准，执行前先加载它；正文文档读取走 `lark-doc`。

## 1. 找到会议，拿到纪要 / 逐字稿

```bash
# 按关键词 + 时间范围找已结束的会议（多个候选时列出主题、时间、组织者让用户选，别擅自挑最近的）
lark-cli vc +search --query "看板 需求" --start 2026-10-20 --end 2026-11-04 --format json --as user

# 会议 → 智能纪要 note_id / 妙记 minute_token（两者独立，可能只有一个）
lark-cli vc +detail --meeting-ids <meeting_id> --as user

# 智能纪要：拿纪要文档与逐字稿（unified 类型用 note +transcript）
lark-cli note +detail --note-id <note_id> --as user
lark-cli note +transcript --note-id <note_id> --as user

# 妙记：读逐字稿 / 待办 / 章节
lark-cli minutes +detail --minute-token <minute_token> --as user
```

- 已有会议链接、妙记链接、纪要文档链接时，直接从对应产物开始，不要绕回搜索
- **提炼需求必须读逐字稿原话**，AI 总结只能当目录用——总结会丢掉口径细节（「活跃客户按 30 天算」这类话往往只在原话里）
- 没有权限时如实告诉用户，并保留已拿到的 `meeting_id` / `note_id` / `minute_token`

## 2. 按清单提炼（逐条记下原话出处）

| 维度 | 要问清楚的 | 落到 spec 的哪里 |
|---|---|---|
| 谁看、在哪看 | 老板周会 / 运营值守 / 门店电视 / 手机 | `audience` → 版式与风格 |
| 要做什么决策 | 「看到逾期就要找人」「决定下季度投哪个渠道」 | 决定 KPI 取舍与排序（最重要的放左上） |
| 指标与口径 | 名称、公式、包含 / 排除哪些状态、去重口径 | `measures`（含 `where`）、`compute`、`filter`、`subtitle` 写口径 |
| 参照 | 和目标比？和上期 / 同期比？ | `time_field`（环比）、目标值字段 |
| 维度与筛选 | 按人 / 部门 / 城市 / 阶段看；要不要时间范围 | `dimensions`、`order`、看板 `default_range` |
| 预警 | 「超过 3 天没跟进就标红」 | `where` + 相对日期 `{"relative":"-3d"}`，`good_when: down` |
| 刷新 | 实时 / 每天 / 每周 | 默认 5 秒实时；只要日报时说明可降频 |
| 数据来源 | 在哪张多维表格、缺哪些字段 | `source.base_url`；缺字段列进 `open_questions` |
| 风格偏好 | 「科技感」「简洁专业」「大气」「老板爱看」 | `design_tone` → 见下表 |
| 优先级 | 必须有 / 有更好 | 必须有的进第一个看板；其余放第二个看板或备注 |

口语 → 设计调性：

| 会上的说法 | design_tone | 推荐风格 | 推荐排版 |
|---|---|---|---|
| 科技感、大屏、展厅、炫 | technical | 霓虹大屏、深海 | 指挥中心 |
| 简洁、干净、专业、汇报用 | corporate | 晴空、燕麦白 | 管理层简报 |
| 大气、稳重、高端、老板看 | editorial | 松针、青瓷 | 杂志式、管理层简报 |
| 监控、值守、信息多、一屏看全 | restrained | 墨石、深烘焙 | 指挥中心、分析工作台 |
| 每天自己看、我的任务 | corporate | 晴空 | 个人工作台 |
| 排名、谁做得好、对比 | corporate | 晴空、墨石 | 记分对比 |

## 3. 写 spec 草稿

- 每个面板加 `provenance`：`[{ "from": "meeting", "ref": "<妙记或纪要链接>", "quote": "张总：逾期率要单独拎出来看" }]`
- 会上没说清的口径 **不要猜**，写进 `open_questions`，并在面板 `notes` 里标「口径待确认」
- 指标名称用业务方会上的原词（他们说「签约额」就别写成「合同金额」）

## 4. 和用户确认（用选择框，不让用户打字）

1. 先报总数：「从会上提炼出 2 个看板、11 个面板，有 3 个口径需要你定」
2. `open_questions` 逐条用选择框问，每个问题给 2~4 个选项 + 「先按默认，稍后再改」
3. 版式确认：按选定排版画 **ASCII 线框图**让用户看一眼（Vizro 做法），例如：

```
管理层简报（销售业绩）
┌────────┬────────┬────────┬────────┐
│ 签约额  │ 赢单率  │ 在途商机 │ 回款率  │
├────────┴────────┴────────┴────────┤
│ 签约趋势（按周，虚线为上期）          │
├─────────────────┬─────────────────┤
│ 商机阶段漏斗      │ 销售签约 Top10   │
└─────────────────┴─────────────────┘
```

4. 确认后跑 `scripts/lint_spec.py`，再按 SKILL.md 的流程同步、编译、出看板

## 5. 交付时附上「需求溯源表」

| 面板 | 来自谁 / 哪句话 | 口径 | 状态 |
|---|---|---|---|
| 赢单率 | 张总 14:32「赢单率按赢 / (赢+输) 算」 | 赢单 ÷ (赢单 + 输单) | 已确认 |
| 跟进超期 | 李经理 14:40「三天没跟进就算超期」 | 下次跟进日期 < 今天 −3 天 | 已确认 |
